# Webhooks: настройка для @eserv.kz

Обновлено 3 сентября 2026. Обработчик уже установлен в E:\CommentAssistantES.
Панель: http://127.0.0.1:8787 → Webhooks.
Приём уведомлений: http://127.0.0.1:8788/webhooks/instagram (локальный адрес; Meta нужен публичный HTTPS).

## Что уже подготовлено

- Проверка URL по GET с hub.verify_token и возвратом hub.challenge.
- Проверка X-Hub-Signature-256 по исходному телу POST и секрету приложения.
- Отдельный порт только для Webhook; панель, настройки и файлы не выдаются через него.
- Постоянная очередь SQLite. Повторная доставка одного ID не создаёт повторный ответ.
- Обрабатываются только comments вашего Instagram. Direct, WhatsApp и чужие аккаунты исключены.
- После выбора Webhooks регулярные запросы списка публикаций и комментариев выключаются.
- Таймер внутри сервера обслуживает уже полученную очередь и задержки между ответами. Это не опрос Instagram. Для события сервер читает сам комментарий и контекст публикации, затем при отправке проверяет существующие ответы.
- На паузе входящие комментарии отмечаются как пропущенные. При включении автоответов старые события автоматически не отправляются.
- 29 автоматических проверок прошли на искусственных данных. Доставка настоящего события Meta ещё не проверена.

## Требования Meta

По официальной инструкции Webhooks от 3 марта 2026 нужны опубликованное приложение, общедоступный профессиональный аккаунт, расширенный доступ (Advanced Access) и подтверждение компании. Разрешения для comments: instagram_business_basic и instagram_business_manage_comments.

Статус «Готово к тестированию» сам по себе не означает расширенный доступ. Рабочие GET комментариев и POST ответа не подтверждают право получать реальные Webhooks: требования к ним проверяются отдельно.

Документация: https://developers.facebook.com/documentation/instagram-platform/webhooks
Проверка приложения: https://developers.facebook.com/documentation/development/create-an-app/instagram-use-case

## Последовательность

1. Откройте локальную панель → Webhooks.
2. В Meta откройте именно приложение Comment Assistant ES → «Настройки приложения» → «Основное» → «Секрет приложения» (App Secret). Скопируйте секрет в поле «Секрет приложения Meta» нашей панели. Сохраните. Он хранится через Windows DPAPI; в чат его не отправляйте.
3. Выберите публичный HTTPS-адрес для обработчика. Для пробного подключения подготовлен Cloudflare Quick Tunnel (см. ниже). Для постоянного подключения используйте стабильный адрес своего сервера или именованного туннеля. Google Sites с политикой конфиденциальности не является сервером Webhook.
4. Введите полный адрес вида https://ВАШ-ХОСТ/webhooks/instagram в поле «URL обратного вызова» нашей панели и сохраните ДО проверки в Meta.
5. В Meta вернитесь к «Настройте Webhooks». В «URL обратного вызова» вставьте этот HTTPS-адрес. В «Подтверждение маркера» вставьте строку из одноимённого поля нашей панели. Нажмите «Подтвердить и сохранить». Переключатель сертификата клиента оставьте выключенным.
6. В Meta включите подписку на поле comments объекта Instagram. Сообщения messages для этого сервиса не нужны.
7. В нашей панели нажмите «Подключить comments для @eserv.kz». Кнопка выполняет:
   POST https://graph.instagram.com/v26.0/17841450147778141/subscribed_apps
   параметр subscribed_fields=comments.
   Маркер Instagram берётся из вашего защищённого хранилища. Ожидаемый ответ Meta: {"success":true}.
   Подписка полей приложения (шаг 6) и включение подписки аккаунта (шаг 7) — отдельные действия.
8. Нажмите «Включить Webhooks и отключить опрос». Начнётся предпросмотр. Старые комментарии не будут отправлены автоматически.
9. Оставьте новый комментарий под своей публикацией с другого аккаунта. В панели должна обновиться дата подписанного запроса и появиться комментарий/причина пропуска. Для проверки автоответа используйте, например, 😂.
10. Только после успешной проверки переключите «Настройки → Что делает сервис → Автоответы» и сохраните.

Meta также предлагает тест поля: «Тест» → «Отправить на мой сервер». Пример с чужим ID аккаунта может подтвердить транспорт, но наш сервис не добавит его в историю @eserv.kz. Тестовый POST не заменяет получение реального нового комментария.

## Пробный HTTPS через Cloudflare

Cloudflare Quick Tunnel передаёт запросы через инфраструктуру Cloudflare, которая завершает HTTPS. Через неё будут проходить JSON-уведомления Instagram. Панель управления, access token Instagram и App Secret по этому туннелю не публикуются.

Установка клиента подготовлена в bin/cloudflared.exe: официальный выпуск 2026.8.3, SHA256 проверен по метаданным GitHub Cloudflare. Источник и контрольная сумма — bin/cloudflared-source.json.

Запуск публичного туннеля не выполнен: автоматическая проверка разрешений потребовала явного согласия пользователя на Cloudflare как внешнего посредника. Локальный сервер уже работает.

После выбора и разрешения такого подключения:
- START.cmd запускает локальный сервер, если он остановлен.
- WEBHOOK-START.cmd запускает только туннель к порту 8788.
- Адрес появляется в data/webhook-url.txt и на странице Webhooks. Вставьте его в поле URL и сохраните в нашей панели, затем в Meta.
- WEBHOOK-STOP.cmd останавливает только этот туннель.
- STOP.cmd останавливает сам сервер.
- Перезапуск пробного туннеля меняет адрес: обновите URL в нашей панели и Meta, снова подтвердите его.
- Компьютер и интернет должны работать. Пробный туннель не устанавливается в автозапуск.

Quick Tunnel предназначен Cloudflare для разработки и тестирования, без гарантии доступности. Для постоянных автоответов нужен стабильный адрес.
Источник: https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/

## Если уведомлений нет

- Убедитесь, что выбран способ Webhooks и сохранён правильный секрет приложения.
- Проверьте публикацию приложения, расширенный доступ и подтверждение компании.
- Проверьте обе подписки: comments в Meta и subscribed_apps для аккаунта.
- При смене пробного адреса обновите URL и повторите подтверждение.
- 403 при проверке URL: неверная строка подтверждения; 403 на POST: неверная подпись/секрет.
- 503 на POST: секрет пока не сохранён; 404 на корне публичного сайта — нормальный ответ, существует только /webhooks/instagram.
- «Последний подписанный запрос» без комментариев аккаунта: возможен тест с чужим ID. Проверьте реальный комментарий.
- Ошибка доступа Graph API требует исправления разрешений/маркера; переключение на опрос само по себе не происходит.
- Непрочитанное событие сохраняется для повтора чтения с увеличением интервала, до 12 неудачных попыток. Ошибки видны в панели.
- Подтверждение URL и ответ success:true ещё не доказывают доставку реальных событий. Заключительная проверка — новый комментарий с другого аккаунта.
